# Use Codex-style thread attachments for user-added files

Carrent follows Codex desktop's shape for user-added resources: importing a single file through the Attach picker or pasting one from the clipboard creates a thread attachment that Carrent and the selected runtime can read for that thread without a second approval. Single-file attachments are copied into Carrent's attachment store as snapshots so conversation history remains reproducible if the original file changes, moves, or disappears. Attachments are global to the local machine rather than limited to the active project.

> **Superseded (drag-and-drop):** This decision originally also said that _dragging_ a single file creates a snapshot Thread Attachment. That drag-specific behavior is superseded by **Local Path Context** (see the Desktop App glossary and PRD #20): dragging a local file or folder from the system file manager onto the conversation surface now adds a structured, live reference to the original absolute path instead of copying a snapshot. Carrent stores no bytes, never enumerates a referenced folder, and owns no snapshot lifecycle for this reference; the selected Runtime receives a narrow, Run-scoped, read-only allowlist for the exact canonical file or canonical directory tree.

> ADR-0010 remains authoritative for Attach-picker and clipboard-paste snapshot attachments; only drag-and-drop behavior is amended here.
