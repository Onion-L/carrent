# Render Skills inline without deleting Composer text

**Status:** needs-triage
**Category:** bug

## Report

Selected Skills should appear as styled inline text inside the Composer's editable content and flow naturally with the user's text. They should not occupy a separate left-hand flex item beside the textarea.

When the Composer already contains text, the user must be able to move the caret to the beginning, type a Skill slash query, select the Skill, and keep all existing text.

## Verification

Confirmed in the current Composer implementation.

- The selected Skill and textarea are separate children of a wrapping flex container, so the Skill is visually adjacent to the textarea rather than part of one continuous editable text flow.
- The slash trigger extends from `/` through the next whitespace, or through the end of the entire input when no whitespace follows the caret.
- For an input such as `/triage已有内容` with the caret immediately after `/triage`, selecting the Skill treats the following Chinese text as part of the trigger and removes it.
- Existing Composer unit tests pass, but they only cover a slash query followed by whitespace and do not cover a query inserted before existing text without a separating space.

Codebase checks:

- Searched the Composer, Skill Catalog integration, draft persistence, existing local issues, and related Desktop App ADRs.
- No existing implementation or duplicate issue provides inline Skill editing with preserved surrounding text.
- No `.out-of-scope/` record exists for this behavior.

## Recommended Outcome

Move to `ready-for-agent` after confirming that "inline" means the Skill marker and normal text participate in one editable wrapping flow while the Skill keeps its distinct icon/color styling.

## Draft Acceptance Criteria

- [ ] A selected Skill appears inside the Composer's editable text flow, using the existing Skill icon, label formatting, and Skill reference color.
- [ ] Skill markers and normal text wrap continuously based on available width instead of forming separate left/right regions.
- [ ] Selecting a slash-menu Skill removes only the slash query that the user typed and preserves all text before and after the caret.
- [ ] Inserting a Skill at the beginning of non-empty Chinese or Latin text preserves that text even when there is no whitespace after the slash query.
- [ ] Inserting a Skill in the middle or at the end preserves surrounding text and leaves the caret in an intuitive editing position.
- [ ] Existing behaviors remain supported: multiple Skills, Backspace removal at the leading boundary, draft persistence/restoration, pasted Skill references, keyboard selection, and final serialized `[$name](path)` references sent to the Runtime.
- [ ] Renderer tests cover beginning, middle, and end insertion; no-whitespace text; inline wrapping; and multiple Skills.

## Out of Scope

- Changing the Skill Catalog, Carrent Bridge, or Runtime prompt format.
- Changing the serialized `[$name](path)` Skill reference contract.
- Redesigning non-Skill Composer controls or Image Attachments.
