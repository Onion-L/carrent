# Avoid Not Found notice during Thread archive

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Treat archiving the currently open Thread as an intentional navigation transition instead of an invalid route.

**Current behavior:**
After archive persistence marks the current Thread as archived, route validation briefly sees the still-open Thread URL as invalid. The generic fallback shows `Thread could not be found.` before the archive flow navigates to the intended sibling Thread or Project view.

**Desired behavior:**
Archiving the open Thread should perform one coordinated replacement navigation without a Not Found notice. A genuinely stale, missing, malformed, or incorrectly owned Thread URL must continue to use the normal fallback and notice behavior.

**Key interfaces:**

- The archive action must record enough transient navigation intent to identify the expected stale route during persistence.
- The global route coordinator must defer to that active archive transition only for the owning Thread.
- Successful archive navigation must clear its transient intent after leaving the archived Thread route.

**Acceptance criteria:**

- [ ] Archiving the current Thread opens the next active sibling when one exists.
- [ ] Archiving the last active Thread opens the Project's New Thread view.
- [ ] Neither successful path shows `Thread could not be found.` or performs an intermediate fallback navigation.
- [ ] A failed archive retains the current route and shows only the archive failure error.
- [ ] A genuine missing or invalid Thread URL still redirects to the nearest valid parent and shows the Not Found notice.
- [ ] Tests cover sibling, last-active, failed-archive, and genuine-invalid-route cases.

**Out of scope:**

- Changing which sibling Thread is selected after archive.
- Adding an archive success notification.
- Changing Archived Thread restoration or permanent deletion.
