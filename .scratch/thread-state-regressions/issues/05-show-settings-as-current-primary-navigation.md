# Show Settings as current primary navigation

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Make Settings the only selected primary-navigation item while the Settings route is open.

**Current behavior:**
Opening Settings preserves `activeWorkspaceId`, so the previous Workspace remains visually selected and keeps `aria-current="page"`. The Settings control also exposes `aria-current="page"` but has no selected styling, leaving two mutually exclusive navigation items semantically current.

**Desired behavior:**
The current primary-navigation item should be derived from the route. On Settings routes, Settings must have selected styling and be the only item with `aria-current="page"`. The previous Workspace identity should remain stored as return context.

**Key interfaces:**

- Workspace rail selection must combine the current route with `activeWorkspaceId`.
- The Settings control must use the same route-derived state for visual styling and `aria-current`.
- Leaving Settings must continue to restore or select a Workspace without clearing useful return context.

**Acceptance criteria:**

- [ ] Opening Settings removes selected styling and `aria-current` from every Workspace rail item.
- [ ] Settings receives selected styling and `aria-current="page"` on the Settings route.
- [ ] Exactly one primary-navigation item exposes `aria-current="page"` at a time.
- [ ] Returning from Settings restores the previous Workspace destination.
- [ ] Selecting another Workspace directly from Settings updates both navigation and stored Workspace context.
- [ ] Renderer tests cover Settings entry, return, and direct Workspace switching.

**Out of scope:**

- Clearing `activeWorkspaceId` while Settings is open.
- Redesigning the navigation rail.
- Changing Settings tabs or their secondary-navigation behavior.
