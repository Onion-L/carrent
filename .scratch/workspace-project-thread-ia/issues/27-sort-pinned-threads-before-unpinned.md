# Sort pinned Threads before unpinned within a Project

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Project thread ordering must place pinned Threads ahead of unpinned ones, with each group sorted by Thread Activity Time descending.

**Current behavior:**
The Project thread list is ordered purely by Thread Activity Time descending; the pinned flag has no effect on ordering. A pinned Thread with older activity sinks below any unpinned Thread with newer activity, making pinning ineffective. The archive flow's "next sibling" redirect target inherits the same pinned-blind ordering.

Regression coverage exists for activity-time ordering, but its fixtures use data where pinned-first and activity-only rules produce the same order, so the gap is undetectable.

**Desired behavior:**
Within a Project group, pinned Threads precede unpinned Threads; within each of the two groups, Threads sort by Thread Activity Time descending. This ordering applies everywhere the Project thread list order is consumed, including the archive flow's choice of which sibling Thread to redirect to.

Spec basis: `PRD.md` in this feature directory — "Within a Project group, pinned Threads precede unpinned Threads; each group sorts by Thread Activity Time descending" — and issue `06-decide-cross-level-discovery`.

**Key interfaces:**

- `getProjectThreads` — the Project thread list selector; its ordering must become two-tier (pinned first, then activity time descending within each tier).
- The Thread model's pinned flag — already exists and drives the pin toggle in the navigation pane; no model change needed.
- The archive flow's sibling-selection — must consume the same two-tier ordering, not a separate sort.

**Acceptance criteria:**

- [ ] A pinned Thread with older activity sorts above an unpinned Thread with newer activity.
- [ ] Within pinned and unpinned groups, ordering is by Thread Activity Time descending.
- [ ] Archiving a Thread redirects to the next sibling according to the same pinned-first ordering.
- [ ] Regression tests use fixtures where pinned-first and activity-only orderings differ, so the two rules cannot be confused.
- [ ] Existing activity-ordering tests updated or extended, not deleted.

**Out of scope:**

- Cross-Project ordering, the Attention view, and scoped search ranking.
- Any change to how pinning is toggled or persisted.
