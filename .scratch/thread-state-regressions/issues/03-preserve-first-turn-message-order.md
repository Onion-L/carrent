# Preserve first-turn message order

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Keep the first user message before its assistant placeholder after a Thread Draft is promoted.

**Current behavior:**
The optimistic assistant placeholder can receive an earlier timestamp than the persisted user message reconstructed during Thread Draft promotion. Timeline sorting then renders an empty cancelled or failed assistant status, such as `Stopped`, above the user message that started the Run.

**Desired behavior:**
Thread Draft promotion and normal Run preparation must preserve the original user message creation time. The associated assistant response or terminal status must always render after that user message, including after persistence and application restart.

**Key interfaces:**

- The accepted Run input must carry the optimistic user message's original creation time through promotion and persistence.
- Persisted user messages must not replace that value with the later Run start time when the original value is available.
- Timeline ordering must remain deterministic for an empty cancelled or failed assistant placeholder.

**Acceptance criteria:**

- [ ] Promoting a Thread Draft preserves the optimistic user message creation time.
- [ ] Normal existing-Thread Run preparation preserves the same value.
- [ ] A first-turn cancellation renders the user message before `Stopped`.
- [ ] A first-turn failure with an empty assistant response renders the user message before the failure status.
- [ ] The order remains correct after App State reload.
- [ ] Tests cover a placeholder created before the Run start time and verify persisted chronology.

**Out of scope:**

- Introducing a general-purpose conversation turn model.
- Reordering unrelated historical messages.
- Changing how non-empty assistant content is rendered.
