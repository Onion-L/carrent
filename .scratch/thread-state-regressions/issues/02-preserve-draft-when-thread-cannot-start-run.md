# Preserve draft when a Thread cannot start a Run

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Prevent archived or mutating Threads from accepting a send that silently discards the user's draft.

**Current behavior:**
An Archived Thread route can briefly render an active Composer. Run preparation correctly rejects the Archived Thread, but the optimistic user and assistant messages are removed without useful feedback, and the submitted draft can disappear. Transient running presentation may also outlive the rejected preparation.

**Desired behavior:**
Archived Thread routes should leave normal Thread navigation without exposing a sendable Composer. If a Run is rejected because the Thread is archived or being mutated, Carrent must preserve the draft, remove only transient optimistic messages, show a clear error, and return the Thread to a non-running state.

**Key interfaces:**

- Archived Thread route resolution must distinguish a known Archived Thread from a genuinely missing Thread.
- Run preparation must reject Archived Threads and Threads undergoing a conflicting lifecycle mutation.
- Rejected Run preparation must restore the submitted content, attached Skills, and pending attachments to the Thread Draft.
- Renderer and Run coordinator state must agree that no Run started.

**Acceptance criteria:**

- [ ] Opening a direct URL for an Archived Thread redirects to its Project's New Thread view without rendering a usable Composer for the Archived Thread.
- [ ] Sending while archive persistence is in flight dispatches no Runtime request.
- [ ] Rejected Run preparation preserves text, attached Skills, and pending attachments as recoverable draft state.
- [ ] Rejected optimistic user and assistant messages are not persisted.
- [ ] The user sees a concise error explaining that the Thread cannot currently accept messages.
- [ ] No Running or Stop state remains after preparation is rejected.
- [ ] Renderer tests cover the archive/send race, draft preservation, error feedback, and final idle state.

**Out of scope:**

- Restoring Archived Threads from the Thread route.
- Permanent Thread Deletion behavior.
- Redesigning Archive confirmation or iconography.
